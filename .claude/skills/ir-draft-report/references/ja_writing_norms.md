# IR 文書の日本語文章規範

報告書ドラフト(`ir-draft-report`)と、レビュー文書(`ir-review-report` /
`ir-review-quality`)の散文に適用する。目的は二つ: 論証にツッコミどころを残さないこと、
LLM が書きがちな中身のない表現を出さないこと。

出典: k16shikano「日本語技術文書の文章規範」
<https://gist.github.com/k16shikano/fd287c3133457c4fd8f5601d34aa817d>(Unlicense)と
「認知リズムを生むための日本語ライティング規範」
<https://gist.github.com/k16shikano/eb2929f13ed19c97188393d297be8432> を IR 文書向けに要約・改変。

## 優先順位

次のドメイン規則が常に本規範より優先する: 確度表現の体系、証拠 ID・不足事項 ID の引用、
defang、逐語抜粋、時刻変換、テンプレートの固定見出し・固定文・記入欄、各 SKILL.md の
執筆規則(強調記法の禁止、メタ表現の禁止など)。

IR 文書では採らない規則: 伏線・緊張の演出、「本章では〜を記載します」の禁止
(章構成の説明は定型として使う)、逡巡→断定の演出(確度は証拠で決まる)、
結びで問いを残すこと(未解決事項は不足事項として明示する)。

## 段落と論証

- 一段落一トピック。段落の最初の文で何の話かわかるようにし、前の段落との関係は
  接続表現(「一方で」「この接続の直後に」「したがって」)で示す。
- 論証は一方向に進める。別解釈の検討を終えてから、結論を一度だけ置く。
- 否定・限定するときは、否定する命題を「」で正確に書き、根拠を一文添える
  (「『VPN 装置の脆弱性が悪用された』と断定するものではありません。装置のログに
  該当する記録がないためです」)。
- 譲歩・限定(「ただし」)を置いたら、その後で必ず論を進める。宙吊りにしない。
- エグゼクティブサマリーは主要な事実と結論を先に出す章であり、上記より優先する。

## 論証の厳密さ

- 確度の上げ下げは必ず証拠と連動させる。根拠なく断定に直さず、根拠があるのに弱めない。
- 区別すべき対象を一括りにしない(役割の異なる外部 IP をまとめて「C2 通信先」と呼ばない)。
  複数の要因を単一の原因に還元しない。
- 因果を主張するときは、その機構を一文で示す。
- 主張の範囲を、挙げた証拠が実際に支える範囲に合わせる。
- 同じ事象の用語・数値・確度を章・節をまたいで一致させる。
- 検出・解決を「必ず」できるかのように書かない。条件付きで述べる。

## 読み手への配慮

- 対象は導入済みの具体名(ホスト名・ファイル名・アカウント名・証拠 ID)で指し、
  「マルウェア」「攻撃者の活動」のような広い語でぼかさない。証拠性のある固有名は省略しない。
- 指す内容が一意に決まらない言い回しは、丸括弧でその場で特定する。
- 行為者が証拠上確定していない事象は受動態で書く(「〜が配置されました」)。
- 読み手は「貴社」(報告書)、または役割名(レビュー文書)で呼ぶ。
- 確度・制約・未確認事項は、該当する所見のそばに書く。

## 書かない表現

- 予告・総括: 「重要なのは〜である」「ここでは〜について見ていく」「まとめると」
  「〜に他ならない」
- 姿勢の宣言: 「正面から扱う」「多角的に」「包括的に」(何をどう見たかを書く)
- 空虚な形容・動詞: 「不可欠」「核心的」「鍵となる」「掘り下げる」「言語化する」
- 中身のない強調: 「非常に」「極めて」
- 根拠のない緩和: 「〜と言えるだろう」(確度体系の「可能性があります」は判定であり対象外)
- 演出: 溜め、修辞疑問、決め台詞の独立段落、帰結の列挙で危険を煽ること
- 文書自身を語る文: 「ここまでで概要を説明した」「次に詳細を見ていく」
- 地の文・見出しのダッシュ(—、―、——)。挿入は括弧、言い換えは文を分ける。

## 冗長の排除

- 一つの主張は一度だけ書く。同じ事象を複数章で扱うときは、詳細を一箇所に置き他は参照する。
- 事実を示した直後に要約し直さない。意味づけの一文だけを置く。
- 接続や評価のためだけの文(「これは注目に値する」)、読者が補える中間説明は書かない。

## 考察段落の拍(3章・4章の考察、サマリー、レビューの総評)

- 文長に変化をつける。論点を短く置き、根拠を長めの文で展開し、短い文で判定を確定する。
  長い断定文を 3 つ以上続けない。
- 証拠・時刻の詰まった段落が 2〜3 続いたら、確定事項を一行で固定するか、視点
  (個別ホスト↔全体像)を切り替える短い段落を置く。
- 列挙したら、本文で各項目を本件の事象(証拠 ID・ホスト・時刻)に対応づける。
  箇条書きの後の一文は、言い換えではなく列挙から読み取れる判断(確度つき)にする。

## 機械チェック

```bash
python .claude/skills/ir-draft-report/scripts/lint_ja_style.py --file <markdown>
```

LLM 定型表現、長すぎる一文、同一文の重複、地の文のダッシュ、段落頭の接続詞の連打を
警告する(ブロックしない)。定型文・引用に由来する警告は残してよい。
